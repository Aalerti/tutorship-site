### 3. Переделать кнопки «Назад» и «На базу»

Сейчас в левом верхнем углу висят две фиолетовые кнопки, которые выбиваются из
тёплой бежево-коричневой палитры сайта.

**Где лежит:** `themes/stack/layouts/partials/buttons/buttons.html`.

> ⚠️ **Не править файл в `themes/stack/` напрямую** — это git-подмодуль, отдельный
> репозиторий (`hugo-theme-stack`, см. `.gitmodules`). Правки туда не попадут в
> коммиты основного проекта.
>
> Правильно: создать **свой** файл `layouts/partials/buttons/buttons.html` —
> Hugo берёт layout из проекта в приоритете над темой, и он переопределит тему.

**Что не так сейчас:**

- Цвета `#6366f1` → `#8b5cf6` → `#3f1f66` (индиго/фиолетовый) не сочетаются с
  палитрой сайта. В коде даже остался комментарий «Зеленый фон» — от какой-то
  прошлой версии.
- Стили лежат в инлайновом `<style>` прямо в partial, мимо общего `custom.scss`.
- Надписи «Назад» / «На базу» стоит заменить на что-то поспокойнее,
  например «← Назад» и «На главную».

**Что сделать:**

- Перекрасить в палитру сайта — переменные уже есть в `assets/scss/custom.scss`:
  `--tutorship-paper` (#fffaf1), `--tutorship-cocoa` (#6f513f),
  `--tutorship-caramel` (#c89a6c), `--tutorship-secondary` (#b9796f).
  Хорошо ляжет бумажная кнопка: светлый фон, коричневый текст, мягкая тень —
  как остальные элементы доски.
- Стили перенести из инлайнового `<style>` в `assets/scss/custom.scss`.
- Поменять подписи.
- Сохранить существующее поведение: скрывать на ширине до 480px.

**Готово, когда:** кнопки в тёплой палитре, не спорят с фоном, стили в `custom.scss`,
файл темы не тронут.

### 4. Боковой декор у досок всех 6 направлений

Слева и справа от каждой доски должны висеть элементы оформления: папки, скрепки,
подвешенные бумажки, концептуальные рисунки — по аналогии с тем, как это сделано
в верхней части страницы вокруг блока выбора направления.

**Что уже есть и как это устроено:**

- `layouts/index.html` — блок `<div class="board-fragments">`: бумажки, стопки
  листов, ленточки с надписями («матан», «сессия», «отчисление»).
- Стили: `assets/scss/custom.scss`, правила `.board-fragments`, `.fragment`,
  `.fragment-paper-one`…`-four`, `.fragment-sticker`, `.paper-stack`, `.note-ribbon`.

**Главная проблема:** сейчас `.board-fragments` — **один блок на всю страницу**,
позиционированный абсолютно с `inset: 17rem 0 auto` и высотой 800px. То есть декор
существует только вверху страницы и до досок направлений просто не достаёт.
Для шести досок нужен декор **на каждый раздел**.

**Как делать:**

- Сделать партиал бокового декора и вставлять его внутрь каждой `.direction`
  (файл `layouts/partials/direction-board.html`), позиционируя относительно самого
  раздела (`.direction { position: relative }` уже стоит), а не относительно страницы.
- **Декор должен различаться от направления к направлению**, иначе шесть одинаковых
  наборов будут выглядеть как копипаста. Варианты: разные наборы элементов, разные
  углы наклона и цвета из палитры, разные подписи на ленточках под тематику
  направления (у КБ — про уязвимости, у САУ — про графы и т.п.).
- Декор обязан быть `aria-hidden="true"` и `pointer-events: none`, как существующий.
- **Переиспользовать осиротевшие рисунки:** при переходе на шесть направлений
  из вёрстки выпали два хороших SVG — `.sketch-laptop` (ноутбук) и `.sketch-symbols`
  (значки), они лежали в удалённой секции `.tutors-section`. Стили для них в
  `custom.scss` остались (`.tutors-sketches .sketch-laptop`, `.tutors-sketches
  .sketch-symbols`), сама разметка была в старой версии `layouts/index.html` —
  поднять из истории git (коммит `ec2225a`). Готовая графика в нужном стиле.

**Осторожно с шириной страницы:** декор по бокам вылезает за пределы вьюпорта.
Существующий `.board-fragments` спасается `overflow: hidden`. Новый декор должен
делать так же, иначе появится горизонтальный скролл — этим уже болеет страница,
см. задачу 7.

**Готово, когда:** у всех шести досок есть боковое оформление, оно не одинаковое,
не перекрывает текст и не создаёт горизонтального скролла на 1920 / 1440 / 900 / 390 px.

**Что сделать:** удалить строки `redirect_url` и `type: "redirect"` из front matter.

**Заодно:** если механизм `type: redirect` больше нигде не нужен, можно удалить и

### 7. Страницу тянет вбок на ~57px

При ширине окна 1440px `document.documentElement.scrollWidth` = 1497px, появляется
горизонтальный скролл.

**Причина:** декоративный SVG `.line-art.sketch-books` в секции «Что внутри»
(`.about-sketches`) вылезает за правый край вьюпорта — его правая граница на 1497px.
Левый `.sketch-notebook` тоже уходит в минус (left: −74), но скролл создаёт именно
правый.

Стили: `assets/scss/custom.scss`, правила `.section-sketches`,
`.about-sketches .sketch-books`, `.about-sketches .sketch-notebook`.

Баг существовал до переделки под направления — проверено, `git diff main` этих
стилей не касается.

**Что сделать:** задать обёртке `.section-sketches` (или общему контейнеру)
`overflow: hidden`, либо ограничить позиционирование набросков вьюпортом.

**Готово, когда:** на 1920 / 1440 / 900 / 390 px выполняется
`document.documentElement.scrollWidth <= window.innerWidth`, при этом наброски
по-прежнему видны.

**Связано с задачей 4** — новый боковой декор рискует создать ровно ту же проблему,
имеет смысл чинить вместе и одним подходом.
